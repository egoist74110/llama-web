llama-web 开发计划

一个 Nuxt + Bun 的单体项目，替代「llama-swap + 图片代理 + 配置生成脚本」这一堆拼起来的东西。

要解决的问题

  • 原来一个请求要经过 图片代理 → llama-swap → llama-server 三层，出了问题不知道是哪一层。
  • llama-swap 界面是英文的，而且「同时只能在线 1 个」这类规则是隐含的默认行为，界面和配置里都看不到。
  • 模型扫描目录写死在脚本里，改个参数要改 JSON、重新生成 YAML、再重启。
  • 看不到模型实时日志、加载进度、生成速度，崩溃了也不知道原因。

做成什么样

  • 一个进程：自己启动和管理 llama-server.exe，同时提供 OpenAI 兼容 API 和中文管理界面。
  • 一个主端口 :5001（本机与局域网，完整功能），外加一个只给 Cloudflare 隧道用的 :8080（只开放 /v1/*，强制校验 key）。
  • 手动启动：源码版双击 start.bat；阶段 5 增加 Windows 桌面套壳，双击应用打开现有管理界面，关闭主窗口即停止服务并结束所有托管子进程。
  • 交付顺序：先做 Windows / macOS 的兼容基础，再做出 Windows 套壳并停下来试用；确认后才准备首个 Windows Release。Mac 套壳与发包另行启动，尚未验证的平台不宣称支持。

不做什么

  • 不支持 vLLM 等其他后端（只留接口）。
  • 不做开机自启、系统托盘；桌面程序只做承载现有网页和管理服务生命周期的薄壳。
  • 不做多用户和登录。
  • 不做历史统计图表（只显示实时速度）。

核心行为规则

模型状态机

stopped ──请求/手动启动──▶ loading ──健康检查通过──▶ ready
   ▲                         │ 失败/超时                 │ 需要切换到别的模型
   │                         ▼                           ▼
   │                      failed（等手动重试）        draining（不接新请求，等在途请求结束，超时强杀）
   │                                                     │
   └──────────────────────── unloading ◀─────────────────┘
ready ──进程意外退出──▶ crashed ──下一个请求──▶ loading（最多自动一次，再失败 → failed；手动启动 / 重试后重新计）

请求路由

  1. 从请求体读取 model；形如 名字:方案 时拆成模型 + 方案，否则使用该模型的「当前方案」。没有 model 字段时使用当前正在运行的模型。
  2. 目标（模型 + 方案）正在 ready → 直接转发。
  3. 否则进入切换队列：当前模型进入 draining → unloading → 目标 loading → ready，然后转发。多个等待同一目标的请求共享同一次加载。
  4. 等待期间，如果是流式请求，每 15 秒发送一次 SSE 注释行 : loading 63% 保持连接。
  5. 目标模型没有配置 mmproj，但请求里有图片 → 直接返回 400 和中文说明，不去加载模型。
  6. GET /v1/models 由 llama-web 自己返回：已启用模型的基础名 + 用户自建方案的 名字:方案；内置「默认」方案不单独列出，即使修改了其参数也不列出。不带方案名仍使用当前方案，已有的 名字:默认 调用继续有效。

参数合并

最终参数 = 全局默认 ← 模型设置 ← 当前方案的覆盖 ← 方案的「额外参数」。表单项每一项都有「继承 / 自定义」两种状态。额外参数里出现了表单已经管理的参数（例如 -c、--jinja）时给出警告，以额外参数为准。--host / --port 由 llama-web 分配，不允许用户覆盖。

来源识别

:5001 来的请求 = 本机或局域网，免 key。:8080 来的请求 = 公网：只允许 /v1/*，校验 Authorization: Bearer <key>（吊销的 key 与无效 key 同样返回 401），通过后在进程内直接交给 /v1 转发逻辑，来源（公网 + key 名）作为参数传入，不经过网络、不使用任何请求头，外部无法伪造。其他路径（页面、/api/*、/upstream/*、静态资源）一律 404，不看 key。Authorization 头不会转给 llama-server。
