Claude 开发指南

做什么、做到哪里看 plan.html；这份指南只管：开几个会话、每个会话用什么模型、发什么提示词。

一个工作包 = 一个新会话

  1. 在 Claude 应用里新建会话，工作目录选 llama-web 项目根目录（这样才会自动加载 CLAUDE.md → AGENTS.md）。
  2. 在模型选择器里选好下面卡片标注的模型。
  3. 复制卡片里的提示词发出去。
  4. 会话结束时，Claude 会告诉你下一个工作包的编号、模型和提示词。照着开下一个会话即可。
  5. 遇到 阶段关口 时先停下来，自己试用，然后按关口里的步骤做审查。
为什么不全程一个对话：每一轮都会带上之前的全部上下文，对话越长每一轮越贵，而且会被自动压缩，早期细节会丢失。为什么不是每个勾一个会话：每个新会话都有两三万 token 的"读文档热身"成本，紧密相关的任务拆开写也容易接不上。

会话规则

这些规则写给 Claude；你不用记，提示词会让它自己读。

  • 开始时：读 AGENTS.md、本指南中当前工作包的卡片、docs/handoff.md 最新一条交接、docs/plan.html 中相关任务与行为规则。用 git log --oneline -10 和 git status 确认起点干净。
  • 范围：只做当前工作包列出的任务。发现需要额外的工作，写进交接记录并告诉用户，不要顺手做。
  • 需要问用户时：遇到计划里没定、会影响行为的问题（改规则、改配置结构、加依赖），先问再做。实现细节自己决定。
  • 测试：纯逻辑模块边写边补 bun test。需要占用 GPU 的真机测试，先告诉用户再运行。
  • 上下文快用完 / 做不完：停在一个能通过测试的干净点，按收尾流程写交接，交接里写清剩下什么，然后让用户用「接续」提示词开新会话。不要硬撑到被自动压缩。
  • 如实：没跑的验证就说没跑，失败就给出输出。

模型怎么选

模型用在原因
Opus 5.5并发、进程、状态机、流式转发、鉴权、下载更新；阶段 1 真机验收时序类、安全类 bug 隐蔽，做错了后面都要返工，值得用更强的模型

Gemini CLIClaude 用量用完时接手读了 AGENTS.md 和交接记录就能接上
本地 Qwen不在开发流程里和项目抢同一张显卡，真机测试时会被卸载

会话收尾流程

每个工作包结束时 Claude 必须按顺序做完这些。

  1. 运行 bun test（以及类型检查），全部通过。不通过就修，修不好就如实说明并停下。
  2. 在 docs/plan.html 里只给已完成并验证的任务打勾，填日期。
  3. 在 docs/handoff.md 顶部追加一条交接（格式见该文件），控制在 30 行以内。
  4. 提交并推送（提交信息里写工作包编号，例如 1-2: store, gguf, scanner, args）。
  5. 给用户的最后一条回复包含：做了什么、验证结果（实际运行的命令和结论）、没做完的部分、下一个工作包的编号 + 模型 + 提示词（从本指南里原样复制）。如果下一个是阶段关口，改为告诉用户该怎么试用。

4-5 一键建隧道（Cloudflare API）Opus 5.5
  • plan 阶段 4「一键建隧道」一项。设置页输入 Cloudflare 操作 token（所需权限：Account · Cloudflare Tunnel · Edit；Zone · DNS · Edit；Zone · Zone · Read），保存到 data/secrets.json（新增字段，secrets 升版本并写迁移），打码显示，不进日志、事件、请求记录和错误输出；server/core/ 下新模块封装 Cloudflare API（可注入 fetch，便于用假服务测试）。
  • 流程：校验 token（权限不足时指出缺哪项）→ 列出 zone → 用户选域名 + 填子域名 → 预览将要做的事（新建隧道、入口规则指向 http://127.0.0.1:公网端口、DNS CNAME 指向 <隧道ID>.cfargotunnel.com 且代理开启）→ 用户确认后执行 → 取回隧道 token 存入 secrets 并打开托管开关。
  • 已存在同名隧道、同名 DNS 记录（尤其指向别的隧道的）要展示现状，让用户选择复用 / 改指 / 取消，不能静默覆盖或删除；失败的步骤可以从中断处重试，不留半成品（创建了隧道但后面失败要提示或清理）。

  • 补测试（假 Cloudflare 服务：成功、权限不足、已存在冲突、中途失败）；README 隧道一节加入新流程；真机验收用用户自己的账号，前先告诉用户要创建 / 修改哪些东西。
