- 决定 33：首次默认关闭；开启后必须明确选择自带 / 文件模式。自带只填 N，生成 `--spec-type draft-mtp --spec-draft-n-max N`；文件模式还选同目录草稿并生成 `--model-draft`。扫描不判断模型能力。
- 用户确认继续使用模型级共享 `draft` 和当前方案 `extraArgs`；切换自带 / 关闭清除共享文件，其他方案下次加载也会受影响，界面明确提示。不新增配置字段、版本迁移或依赖。
- 用户确认额外参数继续原优先级；控件改动只清理当前方案 `--spec-type` / `--spec-draft-n-max` / `--model-draft` / `-md`，不改全局文本。专用控件没改时保留旧参数，包含其他推测解码类型及手写路径。
- 默认 N=3，维持 1–16 整数限制。非法或缺少模式 / N / 文件拒绝；自带模式携带文件也拒绝。已保存旧配置可直接启动，无强制重新确认；旧首次 POST 在开启 MTP 时现在必须提供 `mtpMode`，避免隐式选择。
- 保留首次上下文、全局同步、`useModelStartFeedback` / `useLive` 链路。未改思考快捷上限、调度器、参数合并器、运行库探测、其他反馈或安装包。

## 调用链与数据边界

1. `MtpChoice.vue` 在首次框与 `ProfileForm` 共用；先开关，再选模式，最后 N / 文件。首次不会自动选候选；编辑从已存参数和共享文件恢复配置选择，恢复配置不代表探测模型支持情况。
2. 首次 GET 扫同目录，过滤不完整草稿；上下文继续复用 `previewLaunch`。POST 将 `mtpMode` 传给 `saveFirstSetup` → `applyFirstSetup` → `validateMtp`；先验证所有答案，仍走原两文档保存 / 回退，再启动。
3. 参数编辑只在 MTP 控件值变化时发送 `form.mtp`。`sanitizeForm` 检查输入形状 / 模式 / N；方案保存重新扫描，`saveProfile` 在改文件与方案前校验模板、参数、运行库、设备及草稿。`JsonStore.update` 在同一次模型文档原子写入中保存共享文件和方案参数。
4. `validateMtp` 不采用 `applyFiles` 对当前文件的免复核规则：文件模式必须是当前扫描到的完整 draft，与已保存主模型在同目录。消失、错误类型、其他目录、缺分片或越界引用拒绝，不确认、不启动。
5. 未保存预览用相同 `mtpExtraArgs` 转换临时 form 和 draft，随后调用既有 `previewLaunch`；真实启动继续 `planLaunch` → `buildLaunchArgs`，传参数数组。文件路径空格由原引用和命令展示处理。
6. 共享引用更新时仅重置未改动的 MTP 控件，保留其他未保存编辑。编辑页文件页签保持原接口 / 范围；MTP 专用控件使用已保存主模型的同目录候选，不会顺带保存文件页签未保存的主模型或视觉选择。

管理 API 维持本机 / 局域网免 key 的既有权限模型，没有新增用户角色；跨站 JSON 写入仍由 `admin-origin` 拒绝，公网仍只开放 `/v1/*`。不读取真实配置 / secrets，不新增外部请求、任务、订阅、计时器或模型进程。

并发：扫描异步完成后，实际更新读取 JsonStore 最新文档，同步验证和写入；重复提交替换参数，不叠加。沿用现有最后一次写入生效和重启规则，未新增并发编辑冲突检测。共享文件保存仅影响下次加载；已有运行实例不被隐式重启。

失败：校验 / 模型磁盘写入失败不落盘部分 MTP 设置。首次勾选全局上下文继续现有 `writePair`，模型写失败回退全局字段；失败时不启动。该两文件流程仍是尽力回退，不保证断电时的跨文档事务。启动失败保持已保存配置并走既有实时失败弹窗；取消 / Esc 仅关闭表单。
