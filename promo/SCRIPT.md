## 0 开场：痛点（10 秒）

**旁白**
> 本地跑 llama.cpp，要手写一长串启动参数；再接上 Ollama、vLLM、云端 API，每个客户端都得把地址、密钥、模型名重新配一遍。

**画面**
1. 一个终端窗口里逐字打出很长的 `llama-server --model … --ctx-size … --n-gpu-layers …` 命令，最后报一行红色错误（示意手工调参的麻烦）。
2. 镜头拉远：左边是客户端、Agent、IDE，右边散落着 llama.cpp、Strata、Ollama、vLLM、NInfer（另一台 Linux 机器）、云端 API，每张卡片都带着各自的地址和打码的 key，连线杂乱交叉、闪烁，几张卡上闪 401 / 404。

**字幕**：每换一个服务，就要把地址和密钥重新配一遍。

## 2 新手引导（18 秒）

**旁白**
> 第一次打开，新手引导带你走完：选好模型目录，一键下载官方 llama.cpp 并校验，启用模型，启动。只想当网关？选「只接入外部 API」，三步就好。

**画面（重绘新手引导页，带左侧导航）**
1. 标题「欢迎使用 llama-web」，两张模式卡：「运行本地模型」被选中（强调色边框）。
2. 第 1 步「选择模型目录」：点「选择文件夹…」，路径栏出现 `X:\models`，绿色字「在这个目录里找到 4 个模型文件。」，序号变成打勾。
3. 第 2 步「安装 llama.cpp 运行库」：按钮变成「正在下载…」，状态依次是「正在查询最新版本」「正在下载」「正在解压」，然后绿色「已安装：b11146」，打勾。
4. 第 3 步高亮，点「去启用模型」，转场到模型页。
5. 插一个 2 秒的小镜头：切到「只接入外部 API」，三步卡片依次亮起（添加外部服务 → 读取模型列表 → 在客户端里接入 llama-web）。

**出处**：K 新手引导；决定 14（下载 SHA-256 校验）。注意：llama.cpp **不会**在首次运行时自动下载，画面里必须是用户点击后才开始下载。

## 3 模型：扫描、参数、预估（20 秒）

**旁白**
> 扫描只读文件头，架构、量化、原生上下文一眼看清。第一次启动先确认上下文、思考、视觉和 MTP。参数逐项可以继承、自定义，也能写额外参数；上下文一改，内存预估当场变化，放不下的组合会被拦下来。启动命令完整预览，和实际运行的一模一样。

**画面**
1. 「扫描发现」网格：几张卡片，显示「架构 · 参数量」「量化 · 大小」「原生上下文」和「内嵌聊天模板」标签，点「启用」，弹出提示「已启用「…」，到「已启用」里点启动。」
2. 「已启用」列表：模型行带标签（Q4_K_M、视觉、预估占用 5.1 GB、绿色「放得下」）。点「启动」，弹出「第一次启动「Qwen3-8B」」：上下文 32K、思考「开」、MTP 开关，点「确认并启动」。
3. 编辑抽屉 →「参数」：上下文长度从「继承」改为「自定义」，数值从 32768 改成 131072，下方「显存预估」条从强调色变成琥珀色「有风险」，再变成红色「放不下」；改回 65536，回到「放得下」。
4. 「额外参数」里打字 `--jinja`，「命令预览」里同步出现这一项。

**出处**：B 扫描；C 参数表单、额外参数、命令预览、首次启动确认；D 内存预估三档、放不下不能强制启动。注意：MTP 只展示开关，不说「已在真实模型上验证」。

## 4 方案与自动切换（14 秒）

**旁白**
> 一个模型可以存好几套方案，客户端用「模型名:方案名」直接点名。请求一到自动加载；换模型时自动排队，等旧请求结束再切换。总览里实时看到生成速度。

**画面**
1. 抽屉「配置方案」页：「默认」「长上下文」「关思考」三张小卡片，「当前」标签在「默认」上。
2. 左侧飞来一个请求，内容是 `model: "Qwen3-8B:长上下文"`。侧栏「正在服务」卡片显示「加载中」和进度 63%。总览的大卡片显示琥珀色进度条，然后变成「运行中」，右边的大号数字跳到 42.7 tokens/s，下面画出速度曲线（40 秒前 → 现在）。
3. 再来一个请求 `model: "Gemma-3-12B"`：「请求」小卡片上「排队切换」变成 1，最近事件里出现「Qwen3-8B（长上下文）：运行中 → 已停止」，随后新模型开始加载。

**出处**：决定 6b（方案）、7、8（排队切换）、23（不预加载）；J 总览。可选说明：多个模型同时在线是可开的选项（默认关闭），本片不展开。

## 5 llama.cpp 版本与变体（12 秒）

**旁白**
> llama.cpp 官方版每天检查新版，保留最近两个版本，随时回退。社区分支、你自己的变体也能加进来，每个模型单独选用哪个版本；只要还是 llama-server，参数照样可视化管理。

**画面**
1. 设置 →「llama.cpp 版本」卡片：b11146 标着「当前」，旁边「发现新版 b11429」和「下载更新」；另一行是「回退到此版本」。
2. 点「添加版本」：弹窗里分段选择「选择目录 | 选择压缩包 | GitHub 地址」，选 GitHub，地址栏填 `https://github.com/example/llama.cpp-fork`，出现「这会运行你选的程序」的确认，然后是预览「确认添加」：SHA-256 绿色「与发布页公布的一致」，显示名称填「我的分支」，点「添加」。
3. 版本列表多出一行，带「手动添加」标签。切回模型的「参数」页，「llama.cpp 版本」下拉框选中「我的分支」。

**出处**：A 决定 14、15、34、35；变体支持即决定 34「手动添加」三种来源。注意：不提「从源码编译」（坑位）。

**追加（1.2.0：Vulkan 实验性运行库，约 12 秒）**
4. **旁白**：
> 没有可用的 N 卡？Intel、AMD 显卡和老 N 卡，现在能试用 Vulkan 版。因为up主没有可用的设备，如果遇到问题可以留言。
5. **画面**：
   - 设置 →「llama.cpp 版本」卡片内出现「选择运行库加速方式」黄色提示条，理由为「没有检测到 NVIDIA 显卡驱动……」，两个按钮「用 CPU 版」「试用 Vulkan 版（实验性）」。
   - 光标点击「试用 Vulkan 版（实验性）」，弹出确认框「下载实验性的 Vulkan 运行库？」（弹窗位于选择条下方，不遮挡选择条按钮；说明 Vulkan 版尚未在真机硬件完整验证，CPU 版本仍作为兜底）。
   - 光标点击「下载 Vulkan 版」，弹窗关闭。
   - 卡片内出现 Vulkan 通道区块，标题「Vulkan（实验性，Intel / AMD / 老 N 卡）」，按钮处于下载中状态「正在下载Vulkan……」，右下角浮出「已设置加速方式为 Vulkan（实验性），重启 llama-web 后生效」提示。

**出处**：1.2.0 决定 61（加速方式选择与 Vulkan 实验性运行库）。注意：不说 Vulkan 已验证，强调实验性与社区反馈。

## 6 接入其他引擎：有限管理（18 秒）

**旁白**
> 其他引擎走「接入」：填地址和 key，测试连接就能读出模型列表。跑在本机的，可以写一条启动命令，一键启动、一键关闭；不会写？复制现成的提示词去问 AI。我们只做到启动、停止和转发：支持它们的 API，不等于接管它们。

**画面**
1. 「添加外部服务」抽屉：名称打字 `Strata`，地址 `http://127.0.0.1:8080/v1`，启动命令 `/bin/zsh "/Users/me/strata/start.sh"`。展开「不知道怎么写启动命令？」→「让 AI 助手帮你写」，点「复制这段话」，按钮变成「已复制」。
2. 接入卡片「Strata」：点「启动」，状态是「正在启动，等它列出模型… 已等 6 秒」，然后变成绿色「在线」，下面出现模型标签 `Strata-qwen3-32b`，「独占本机」开关是开的。最后点「关闭」。
3. 第二张卡片「NInfer」：「在本机运行」是关的，地址是 `http://192.168.1.50:8000/v1`（另一台 Linux 机器），只有「测试连接」。
4. 三档对比图（2 秒）：
   - **原生管理**：llama.cpp 官方版和变体，可以下载、调参、写额外参数、加载切换。
   - **启动 · 停止 · 转发**：本机的其他引擎（Strata、Ollama 等）。
   - **仅转发**：其他机器上的服务（NInfer、vLLM）和云端 API。

**出处**：F 接入、决定 56（启动命令、关闭本次运行启动的进程、独占本机）；决定 57（边界）。注意：「关闭」只对本次运行里由 llama-web 启动的进程有效，画面里就是这种情况。

## 7 一条请求经过什么（10 秒）

**旁白**
> 每个请求都走同一条链路：图片先压缩，上游的密钥由 llama-web 代填，记录里只有 token 和耗时，不存对话内容。

**画面**
1. 请求包从客户端飞进 llama-web（`:5001`），依次经过「图片压缩」（最长边 3024 → 896px）和「附上上游 key」两站，到达 Strata，再以流式文字的形式返回。
2. 切到「日志 → 请求」表：新增一行，内容是「局域网 · Strata-qwen3-32b · 200 成功 · 2.31 s · 1234 → 567 · 1 张，3.1 MB → 186 KB」。表头上方写着「请求记录不包含对话内容，也不包含 Authorization。」

**出处**：G 图片压缩（默认最长边 896、JPEG 90）；H 请求记录。

**追加（亮点：不只是聊天）**
3. 请求表里再出现一行 `audio/speech`：「局域网 · TTS-诗歌剧_ZH · 200 成功」。画面角落浮出小字「本片旁白：另一台机器上的 TTS → llama-web 转发」，旁边画一个声波图标。
**出处**：2026-10-13 实测：经 llama-web 调用上游 `/v1/audio/speech` 返回 200 音频。注意：只写实测过的「语音合成」；生图、视频没有实测，不写。

## 8 公网访问（10 秒）

**旁白**

**画面**
1. 公网访问引导：「第 3 步 / 共 5 步」，三张选项卡「一键完成（推荐）」「我在 Cloudflare 网页上自己建」「没有域名，用临时地址」。
2. 执行进度：隧道、入口规则、DNS 记录逐行打勾，状态变成绿色「隧道已连通（4 条连接）」。
3. 客户端地址 `https://llm.example.com/v1`；API key 列表里有「手机」「server-1」两把，状态都是「可用」。

**出处**：I 公网访问（:8080 只绑 127.0.0.1、只开放 /v1/*、需要 key；一键建隧道；临时地址）。注意：临时地址没有可用性保证，不要渲染成可以长期使用。
